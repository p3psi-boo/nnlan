# 候选地址生命周期

候选只是连接线索；每次连接仍须验证目标公钥，路径迁移仍须通过加密 challenge/response。
不把观察到一个 IP:port 当成已建立邻接，也不因收到新候选自动建立全连接。
跳过“本机地址”拨号只依据实际本地接口或显式配置；邻居上报的线索不参与这种过滤，
避免错误观察把另一个真实 peer 的地址屏蔽掉。

## 三种来源，一份最多 16 项的广告

- **显式配置**：`endpoints` 优先保留，直到管理员修改配置；不因邻居掉线删除。
- **本地接口**：整体替换主机地址快照，删除地址、接口 down 都撤回对应自动候选。
- **邻居观察**：按已认证邻居公钥保存一项观察。该邻居看到新 NAT 端口时替换旧项，而不是永久追加。

多个邻居观察到同一地址时只公布一次；其中一个断开不会误删其他活跃邻居仍在确认的地址。
观察来源最多 128 个，受实际邻居上限约束；邻居断开立即移除其观察，未刷新的动态来源 30 s 后过期。
过期由 100 ms 的维护任务检查，变化时立即重新发布。显式配置不参与动态过期。

显式地址之外，本地和观察候选交替填充剩余名额，避免多网卡把 NAT 公网候选完全挤掉。
最终广告排序、去重，仍由同一节点记录签名与传播，没有引入第二种发现协议。
相同地址的心跳只刷新来源存活时间，不每秒重新签名一份相同地址广告。

## 有界交错尝试

一个失效候选不再独占整个 8 秒握手窗口：同一身份最多有两条独立主动 Noise 握手，
新候选最早间隔 500 ms；每条握手仍绑定自己的准确端点、目标公钥和会话 ID。
同一未完成端点不重复占位，不复用同一个 Noise flight 来接受多个来源。
单身份另允许最多两条被动握手，仍受全局共享的 64 条未完成握手上限约束；UDP flight 地址仍最多 128。
GGB3 仅保留相邻节点的候选握手，没有独立端到端握手或会话。

只有验证目标身份且接纳成功后，才取消其他本机主动候选握手；错误公钥或错误来源的回复不会
取消仍可能完成的首选路径。取消 flight 的晚到回复不会重新覆盖已选路径。
被动握手可完成双方同时发起的连接；现有换钥、路径 challenge、FEC 世代隔离与邻居上限不变。

实际业务请求创建 8 秒直连需求窗口；每秒维护任务会继续尝试，所以单次请求也能推进后续候选。
后台重试不延长需求窗口，已连接、封禁或失去信任会停止对应尝试；发现记录本身不创建需求。
握手仍按 400 ms 重试、8 秒到期，因此需求停止后，已发起握手还可完成或自然到期。
配置 peers 按原有语义持续尝试；普通自动邻居没有新流量就不会永久背景拨号。

两条主动握手均被黑洞占用时，后续候选仍等待名额到期；没有把所有 16 个候选同时发包。
更多失效候选、高 RTT、全局握手名额竞争与长期失败下的调度仍需扩展验收。

自动候选排除 unspecified、multicast、广播、link-local、overlay 地址池和不匹配监听地址族的地址。
非 loopback 监听时不接受邻居给出的 loopback 自动候选；IPv4-mapped IPv6 规范化后再校验。
处于 DAD tentative / failed、deprecated 或 down 状态的本地自动地址不参与公布。
明确配置的地址保留管理员意图，不把自动过滤策略偷偷施加到手工候选上。

## 接口刷新不阻塞转发循环

通配监听使用一个只读 `NETLINK_ROUTE` socket 订阅 link、IPv4 地址和 IPv6 地址通知。
通过 [Tokio AsyncFd](https://docs.rs/tokio/1.53.1/tokio/io/unix/struct.AsyncFd.html)
等待非阻塞 fd，不引入常驻 `ip monitor` 子进程、新依赖或第二份增量地址数据库。
通知只表示“重新查询”，地址真值仍来自 `ip -j address show up` 的完整快照；不从通知负载直接接受候选。
订阅在首次 worker 查询之前建立，查询期间发生的变化留在 socket 队列中。

第一个事件开启 100 ms 合并窗口，后续事件不延后截止时间；持续变化也会定期取快照，
而不是等网络完全安静才更新。无变化时每 15 s 对账，低于动态来源的 30 s TTL；
既刷新来源寿命，也修复漏通知。接收缓冲区固定 8 KiB，截断通知和 `ENOBUFS` 都触发全量对账。
这遵循 [Linux Netlink 通知与消息模型](https://www.kernel.org/doc/html/latest/userspace-api/netlink/intro.html)，
不把每个通知对应成必须永久保存的事件。

同一 worker 最多一个快照子进程，超时 2 s、stdout 上限 1 MiB，与 Engine 的 channel 容量为 1。
查询失败不删除配置；动态快照在 TTL 到期后撤回，后续成功查询可恢复。
订阅建立或接收出错时保留 5 s 轮询与重开尝试，不退出 daemon。
指定单一监听 IP 时直接刷新该地址，不打开订阅 socket 或运行接口扫描命令。

查询通过 [Tokio 异步进程接口](https://docs.rs/tokio/1.53.1/tokio/process/struct.Command.html) 执行；
超时/退出会取消查询并终止仍运行的子进程，转发循环不等待接口查询。
通知接收取消后可以继续等待；worker 停止时由 fd 所有权释放订阅。
交付的 systemd unit 已允许 `AF_NETLINK`，没有新增 capabilities 或主机服务依赖。

## 换路径与密钥生命周期

新 NAT 地址先验证实际返回路径，再建立新的 Noise / FEC 世代。
旧世代的延迟地址观察不参与更新候选；只接受当前活跃密钥世代的观察，防止旧地址重新覆盖新地址。

每个 peer 最多保留 4 个传输密钥世代；总会话上限仍为 8192。
频繁迁移时，**新握手通过身份验证后**才按需淘汰最旧的非活跃世代。
未验证的 initiation、损坏的握手回复不腾挪既有密钥；旧活跃密钥在新会话安装前继续保留。
这避免四次快速迁移后等待邻接失效定时器，而不是简单提高或取消容量上限。

## 验证

```bash
nix develop --command make check
nix develop --command make e2e-candidates
nix develop --command make e2e-interfaces
```

普通测试覆盖 40 次观察替换、共享来源、TTL/配置优先级、来源与广告容量、地址解析过滤、
旧密钥观察隔离、20 次连续换钥及未验证握手不淘汰已有密钥。

内核测试使用独立 namespace、真实 NAT/conntrack 和三个 daemon：

1. A/B 内网地址相同，只配置 R；阻断 A/B 直连以便单独检验 R 的观察来源。
2. 连续 20 次替换 A 的 SNAT 端口并删除对应 UDP conntrack，超过广告容量 16。
3. 每次确认 A 和 B 看到的新签名候选均已替换旧端口，R 的认证邻接也使用新端点；2048 字节加密回显通过。
4. 在 R 增加、替换接口地址并执行 down/up，A/B 看到的签名候选相应增删。
5. 全程校验 boot ID 不变，验证双栈多跳；解除直连阻断后，用最新候选升级直连并再次验证双栈通信。

本机无损测试为每次迁移设置 6 s 上限，用来捕获“旧世代占满→等邻接超时”的回归；不是公网恢复时间承诺。
产物 `target/e2e-candidates.json` 记录每次迁移耗时、实际二进制摘要和内核版本。

候选调度回归还包含：

- 普通测试验证两条主动/两条被动与共享 64 条上限、同端点不重复占位；
  错误来源和错误身份不取消有效候选，取消后的迟到签名回复不切换已选端点。
- `make e2e-nat-topologies` 只用一次用户请求触发发现后的候选切换，不用持续 ping 掩盖后台调度缺失。
  旧二进制同样只发一次请求，35 秒内未升级；新版本 hairpin 三次独立复测为 1.067 / 1.058 / 1.048 秒。
  这是连接建立观测，不是转发 RTT 或吞吐基准。旧版本持续 ping 的约 9.3 秒是另一种请求模式。
- hairpin 关闭时，第 20–22 秒的失败路径计数保持 80，证明没有新需求时探测停止；
  随后的主动请求仍可通过中继通信，而不是关闭整个节点。
- `make e2e-ipv6-discovery` 在真实 IPv4 丢弃与 IPv6 有状态防火墙下，单次请求约 0.73 秒升级 IPv6；
  包含中继回退、恢复，以及 R 离线后超过 65 秒无应用流量仍保留必要直连边。

后两项都使用真实 TUN、双向 IPv4/IPv6 应用流量与主动 trace；没有注入虚假的候选完成事件。

接口事件专项 `tests/e2e/interfaces_netns.py` 使用两个真实 daemon 与内核 rtnetlink：
逐项检查 IPv4 地址替换、接口 down/up/删除、IPv6 增加及 preferred lifetime 变化在 2 s 内传播到另一节点。
另检查 401 次地址操作合并、真实订阅组、快照命令卡死时的加密流量与子进程超时回收、
查询持续失败后的动态来源到期，以及没有新事件时的周期恢复。静默 16 s 窗口记录实际查询次数。
快照故障只注入该夹具 A 进程的 `ip` 包装命令；成功查询始终执行真实系统 `ip`，不伪造地址 JSON。
最终验证双向双栈 TUN、主动 trace 与 boot ID 不变，报告 `target/e2e-interfaces.json`。
这些局部事件测试不等于多 namespace 千进程压力、内核通知溢出的强制复现或任意网络管理器验收。
