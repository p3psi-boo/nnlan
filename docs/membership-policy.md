# 成员引荐、撤销与本地封禁

## 最小操作面

```bash
nnlan --config ./state/nnlan.toml members
nnlan --config ./state/nnlan.toml members deny PUBLIC_KEY
nnlan --config ./state/nnlan.toml members allow PUBLIC_KEY
```

`PUBLIC_KEY` 是完整节点公钥，不按可能重名的节点名称修改策略。
`members` 返回当前可信成员和本地 `denied` 公钥集合；`peers` 仍提供已发现的签名记录及 `trusted` 状态。
离线预配置可在配置顶层填写 `denied = ["完整公钥"]`，随后启动 daemon。

封禁优先于配置 peer、实际握手和任意层级引荐。配置 peer 不被自动删除，保留原来的连接名额与入口意图；
解除封禁后正常尝试连接。`allow` 只移除本地否定，不凭空增加可信成员、不授权子网或出口。
重复 deny/allow 幂等；最多 4096 个本地否定项，自身身份不接受此类修改。

本地修改经 owner-only 管理 socket 执行，原子持久化配置后应用，在应用完成后回复。
持久化失败返回错误；提交后若内核协调失败，daemon 停止而不继续运行半应用策略，已有防回落规则保留。

## 一份签名记录，同时表达邻接与引荐

没有新增全网黑名单广播、撤销证书服务器或第二套成员协议。
已认证的直连邻居是本地信任起点；其有效签名邻接记录引荐其他节点，逐层传播。
节点发布更高序号、移除了某条邻接的新记录，即撤回它对该邻居的引荐。
同一节点的较旧序号不替换当前记录；记录有效期仍为 60 秒，稳定时每 15 秒刷新，实际状态变化立即签发。

替代引荐仍然有效。例如 A 分别通过 C 和 D 获知 B，C 撤回 B 后，D 的有效引荐仍能使 B 成为成员。
A 明确封禁 B 时，C/D 的引荐均不覆盖 A 的选择。A 封禁中间节点 C，只切断经过 C 的信任链；
其他可信起点存在时，其下游节点不被无条件连坐封禁。

本机过时的签名记录不作为信任起点。最后一条真实直连消失后，缓存中的 A→C→D→A 循环
不会自行维持成员资格。其他节点的路径随记录传播、更新或过期收敛，本地命令的成功不代表全网同步完成。
这是本地身份策略，不是全网一致的撤销：其他节点可以继续信任该公钥；新公钥是另一身份。
远端记录最高序号只保存在本次运行的有界记录表中，本地否定集合则跨重启持久保存。

## 数据面与路由

封禁直连节点时清除其握手、会话、FEC/RTX、路径挑战及邻居状态，拒绝新的入站与出站握手。
可信集合缩小时，清除失去资格节点的直连尝试与诊断请求，清空逐跳待发/FEC/RTX，并删除其 VIP 路由。
多跳数据仍检查声明源身份的成员资格和目的路径，被封禁源身份经另一 relay 转发也会被拒绝。
GGB3 信任中继转述来源；这不提供针对恶意可信中继冒用另一有效成员身份的端到端密码学证明。

已经分片的逐跳发送队列没有上层身份标签，因此策略撤销时清空有界待发送、FEC 和 RTX 队列，
而不增加第二套逐片访问控制索引。保留存活链路的密钥与递增帧编号，不复用序号；其他流可能短暂丢包。
已经交给内核或发到远端的包不具备追溯撤回语义。

选中的 Subnet Router / Exit Node 被封禁时，保留原选择和防回落规则：状态变为 blocked / unreachable，
不替换成同前缀的其他发布者，不切换其他出口，也不回落到本地网络。显式 allow 后可恢复原选择。

## 验证入口

```bash
nix develop --command make check
nix develop --command make e2e-membership
nix develop --command make e2e-subnet
nix develop --command make e2e-exit
```

普通测试覆盖签名撤回与替代引荐、过时本机记录的循环、入出站握手拒绝、队列清空后的编号连续性，
以及独立进程的持久化/重启/写入失败。内核测试使用真实 TUN、双路径四节点、双栈应用接收日志、
实际路由删除和重复入站握手；子网/出口测试验证封禁后的保持选择与防回落。
以对应 `target/e2e-*.json` 的二进制与测试摘要及实际命令退出状态为验收依据。
