# 弱网与独立修复策略

## 两个开关，不增加协商协议

```toml
[repair]
fec = true
rtx = true
```

两项缺省均为 `true`，允许独立关闭；修改配置后重启 daemon。
策略作用于本节点每条邻接的**发送方向**，路径迁移和换钥创建的新 Link 继承同一策略。
`plan`、`status.repair` 和 `status.neighbors[].link.repair` 显示实际配置。

- `fec=false` 不产生 parity，仍发送组边界，让对端检测缺片并反馈。
- `rtx=false` 同时阻止 NACK 触发和 RTO 触发的逐跳源片重传。
- 接收解码、FEC 恢复、ACK/NACK、RTT/丢包反馈、拥塞控制、pacer 和原有共享保护预算保持启用。
- 关闭 RTX 后仍保留有界源片记录用于 ACK/BWE，超时清理，不把缓存当成无限可靠队列。
- 接收方可以使用不同的发送策略；关闭本机 FEC 发送不拒绝对端的 parity。
- 开关不关闭 Noise 认证/加密，不改变应用 TCP 自身重传，也不禁止握手重试或控制记录定期发布。

这不是移除默认 FEC/RTX 的性能捷径，而是诊断和对照试验的明确配置。默认机制与原来的上限一致：
最多两次重传、源缓存寿命 1 秒、源缓存 2048 项；保护预算和迟滞见 [传输实现](transport-implementation.md)。

## 真实 Linux 矩阵

```bash
nix develop --command make e2e-weaknet
# 单项检查：
nix develop --command python3 tests/e2e/weaknet_netns.py --mode fec_only --profile random_loss
```

与基础九套 `make e2e` 分开运行，便于保留较长故障矩阵的原始证据。
仅使用本次创建的两个 namespace/veth，两个真实 daemon、双栈 TUN、Noise、RS 和 UDP socket；
不修改宿主机路由、防火墙或网络参数。

四种发送策略（双开 / 仅 FEC / 仅 RTX / 双关）分别经过八个实际内核故障：

| 场景 | A→B | B→A |
|---|---|---|
| clean | 无损 | 无损 |
| random_loss | 独立 5% 丢包 | 无损 |
| burst_loss | Gilbert–Elliott：3% / 40% / 90% / 0.1% | 无损 |
| reordering | 延迟 30 ms，乱序 25%，相关度 50% | 无损 |
| duplication | 复制 15% | 无损 |
| reverse_loss | 无损 | 随机丢弃 60% |
| rate_limit | 延迟 20 ms，限速 1 Mbit/s | 无损 |
| mixed | 延迟 20±8 ms、丢包 4%、乱序 20%、复制 3%、限速 3 Mbit/s | 无损 |

`tc netem` 使用有限 128 包队列和固定随机 seed；各故障语义见
[iproute2 netem 手册](https://man7.org/linux/man-pages/man8/tc-netem.8.html)。
故障作用于加密底层报文，不按明文帧类型选择丢弃；`reverse_loss` 丢失反向 ACK **及其他控制流量**，
不是声称只丢 ACK。固定 seed 也不保证四种策略经历相同的业务包丢失序列，因为冗余会改变实际报文数量。

每项并行发送 IPv4 / IPv6 各 400 个 768 字节应用 UDP 包，按序号验证完整 payload、实际源 VIP、
应用重复交付和接收次序。记录每包同一内核的 monotonic 时间差，给出成功包的 p50/p99/p99.9；
短样本尾分位数接近最大值，不是跨主机时钟测量或延迟 SLA。

验收断言包括：

- 无损组两种地址族全部收到；本测试负载下，乱序/复制/反向丢包两族各至少收到 95%，
  随机/突发丢包各至少 80%；主动过载限速及混合场景保留实际丢包数，不承诺无损。全部场景没有重复交付。
- 关闭的修复机制发送计数始终为零；启用机制在整组故障中确实产生修复/重传。
- 随机、突发及反向丢包从内核 qdisc 统计确认实际丢弃；乱序到达实际应用，复制场景观察密文重复被拒绝。
- 每 250 ms 观察 daemon 状态与 RSS，源缓存不超过 2048 项、队列字节不超过协议容量上界；
  boot ID 不变、邻接保持。采样峰值不是精确瞬时最大内存或资源耗尽证明。
- 移除故障后，真实双栈 ICMP 和逐跳加密覆盖回显恢复，不通过重启掩盖损坏状态。

报告为 `target/e2e-weaknet.json`，包含内核、二进制/脚本摘要、32 组原始接收样本、qdisc、
修复计数、状态和 RSS 采样峰值。全组结束前 `ok=false`，每组原子保存；完整通过后才写 `ok=true`。
四种策略各自启动新 daemon；同一策略内的场景共享会话和控制器，场景间清除故障并留出旧源缓存过期时间。
这是一组功能、负向对照与有界状态验收，不是独占 CPU 的性能基准、每种网络的无丢包承诺，
也不覆盖所有高时延、多跳、长时间拥塞或大量节点组合。

## 精确帧级对照

普通 Rust 测试另外给出可重复、与随机网络无关的证明：

- 同一消息在四种策略下丢弃相同原始源片，只有双关模式未恢复；仅 FEC 与仅 RTX 分别记录对应机制。
- 接收侧关闭自己的两项发送修复，仍能恢复对端 parity 并发送 ACK。
- ACK 全失且持续收到 NACK 时，每个源片最多两次重传；RTX 关闭时始终零重传，最终队列/缓存归零。
- 配置缺省、独立开关、保存/读取、错误字段和错误类型均有校验。
- 真实 UDP 端口迁移后，新密钥世代保留非默认发送策略，与使用默认策略的对端继续互通。
- 预算拒绝后的重传等待一个 RTO，不被持续 NACK 或轮询绕过；预算恢复后仍可发送。
- 乱序的负向时延差参与梯度；旧梯度不反复降速，反馈超时仍对排队流量降速。
- 64 kbit/s 的真实 ACK 样本可触发有限提速，只有过期丢失样本不触发；不降低原有丢包估计门槛。

## 2026-09-20 实测与修复

本地 release 摘要 `f96a7889395ed72c58e50e9d4511b98cc765026b2cd1d45bddb0fccbd5445d02`，
32 组已完整通过较强的交付门槛。每格表示接收的 IPv4 / IPv6 包数，各发送 400 包：

| 本机发送策略 | 随机 5% 丢包 | 突发丢包 | 1 Mbit/s 过载限速 | 混合故障 |
|---|---:|---:|---:|---:|
| FEC + RTX | 400 / 400 | 400 / 400 | 357 / 125 | 400 / 400 |
| 仅 FEC | 396 / 395 | 387 / 384 | 386 / 110 | 400 / 400 |
| 仅 RTX | 400 / 400 | 400 / 400 | 392 / 174 | 400 / 400 |
| 双关 | 381 / 379 | 381 / 382 | 388 / 183 | 386 / 374 |

四种模式的无损、乱序、复制和反向丢包场景均为 400 / 400，全部场景零重复交付。
限速场景是主动过载，结果保留损失及地址族差异；该样本显示修复有带宽代价，
不把“FEC 总能增加 goodput”当成结论。公平性、长时间过载和更多 seed 仍待扩展。
生成器每轮先发 IPv4 再发 IPv6，共享 FIFO 底层；过载结果不是两个 IP 版本的性能比较。
此次抽样最大源缓存 201 项、排队字节 2086、单 daemon RSS 7496 KiB；
所有场景的实际重传数均未超过对应源片的两次重传上限。

首轮诊断暴露两类问题：

1. 预算拒绝的同一个重传被每次轮询/NACK 重新排队，反向丢包样本累计 194449 次队列拒绝。
   现加入 RTO 退避，源缓存寿命与发送次数上限不变；精确测试验证退避不被 NACK 绕过，预算恢复后仍能重传。
2. 乱序的负向时延差被丢弃，旧正梯度又在无新样本时反复降速；降至低速后，300 ms 内收不到 12000 字节，
   又失去恢复资格。现保留负向差、只在新样本到达时按梯度调整，并用真实 ACK 支持低速探测，
   丢包估计仍保留原门槛。首轮“双关、乱序之后的复制场景”仅收到 7 / 2，修复后收到 400 / 400。

首轮 `target/repair-weaknet-before.json` 仅作为缺陷诊断证据，其旧版 liveness 断言过弱，
不作为本轮验收通过的依据；当前测试已加入 95% / 80% 交付门槛及实际乱序断言。
最终日志为 `target/repair-final-weaknet.log`；`target/repair-controller-check.log` 包含 99 项普通测试、fmt 和 Clippy。
以上测量与其他功能/VM 回归并行运行，不用于独占 CPU 的吞吐或尾延迟比较。

同一修复版本的基础九套 netns 回归和静态开机 / DHCP 两套真实 VM 回归均已通过，
日志分别在 `target/repair-final-e2e.log`、`target/repair-final-boot.log`、`target/repair-final-dhcp.log`。
`target/repair-final-audit.json` 核对当前本地 release、Nix 包和各报告的摘要；
