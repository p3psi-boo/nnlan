# 组网软件：已定方向与设计待决项

更新：2026-09-22。本文区分用户已确认的要求与实现建议；建议不代表已定案或已实现。

当前代码进度见 [implementation-status.md](implementation-status.md)：已接通 Rust 双栈 TUN、多跳加密、
Subnet Router 和 Exit Node；具体已测范围与剩余验收以该文件为准。

## 已确认

- 第一版交付 Linux 上可运行的 MVP。
- 实现语言采用 Rust，优先考虑长期吞吐、低延迟与性能可控性。
- 地址池采用 `33.0.0.0/8` 与 `fd33::/16`，后者替代此前的 `fd33::/7`。
- 填写 peers 即可引导连接，不依赖固定中心协调服务器。
- 经已连接节点发现其他节点，并尝试建立 P2P 直连。
- 网络定位为私有组网；配置 peers 时必须携带预期对方公钥。
- 首次连接单向配置即可：A 填写 B 的连接地址和公钥，握手成功后 B 自动接纳 A；B 无需预先配置 A 的公钥或进行人工批准。
- 入网不额外要求账号、白名单批准或共享邀请凭据。公钥固定用于验证目标身份，不视为保密的入网密码；当前成员规则不构成密码学封闭的私网准入边界。
- 成员信任允许传递：已信任成员可引荐新成员，本机验证引荐关系及目标身份后自动接纳，无需逐节点手动批准。成员信任不等于接受其子网或默认路由。
- 第一版按百节点日常使用、千节点规模验收设计；千节点不是协议硬上限。
- 千级规模满足当前产品目标，不为万级规模预先引入 DHT 或紧凑树路由。采用精简全网链路状态，
  先消除地址/路由计算的重复扫描，再按测试结果改进有界状态同步；保留现有功能及权限语义。
- 每个节点维护有限数量的直连邻居，不向所有发现的节点建立 P2P 连接。
- 所有节点默认启用 relay 能力；relay 不等于启用 Exit Node、发布内网或接受他人的路由。
- 一个进程实例只管理一张网络；多张隔离网络通过多个实例运行，各自使用独立身份、配置、状态和 TUN，不引入进程内多租户。
- 采用单层逐跳加密，不叠加独立端到端加密。成员与中继均可信，中继可读取/转发内层 IP 流量；认证、防重放、FEC 和有限重传保留。
- 支持多跳转发，例如 `A → C → D → B`；提供 trace 子命令显示中转节点。
- IPv4 地址自动分配，包含碰撞检测与处理，不将公钥哈希截断视为唯一性保证。
- 支持 Exit Node 与 Subnet Router。
- Exit Node 失联时保持阻断，不自动回退本地出口；出口恢复后继续使用，只有用户显式停用出口模式时才恢复原路由。
- 节点可以发布内网前缀，其他节点手动接受；发布项同时以发布节点和前缀区分。
- 多个节点可以发布相同前缀且代表不同物理内网；本机对同一前缀最多接受一个发布节点。
- 极简指减少概念、重复机制、配置负担和维护面，不指删除功能。
- 文档中的 FEC、保护预算、发送整形等弱网能力属于产品要求；只完成加密隧道和 ping 的阶段是开发里程碑，不是完整 MVP 验收。

## 实现建议（待协议设计确认）

### 1. 一个程序，一条主要数据路径

一个二进制提供 daemon 与管理子命令；CLI 通过本地 Unix socket 查询与修改状态。
普通节点、引导节点、中继、Exit Node 和 Subnet Router 是节点能力，不是五种独立服务。
代码先用清晰模块划分，避免一开始照搬旧设计中的九个 crate、插件框架和多种传输后端。

主路径为 TUN、路由、保护调度、认证加密、UDP；接收端先认证再向 FEC 解码器提交分片。
确切封装次序、FEC 保护范围与反馈线格式需要通过独立协议测试冻结。
不承诺兼容 WireGuard 或 UU 的线上协议；复用成熟密码实现，不自行设计密码算法。

单实例单网络已确认。实例间不自动交换发现信息、引荐、拓扑或路由，管理 socket 与持久化状态分别命名。
多个 TUN 本身不隔离系统路由；由于不同实例可能使用相同地址池、相同内网前缀或不同 Exit Node，Linux 多网络部署建议将实例放入独立 network namespace，分别配置其底层连通性。
此处 namespace 为部署建议，不改变单实例的组网协议；不为多实例提前开发一套容器或网络编排系统。

### 2. 一份带宽预算，而非多个相互竞争的控制器

TWCC 风格反馈、BWE、PacerV2/Burst AIMD、FEC 抑制器、RTX 早晚准入与债务账本组成闭环。
原始数据、FEC、RTX、探测和控制流量均计入实际发送预算；高优先级流量也有上限。
路径反馈与估计按路径隔离；本节点出口调度再提供共享上限和公平性，不误把每个 peer 的估计相加当成独立出口容量。
随机丢包分类必须包含样本有效性、队列/时延信号和持续过载回退，避免无条件维持速率。

IP 数据保持报文语义，不全部放进可靠有序 KCP 流。
控制面是否需要 KCP，依据控制消息大小、重试语义和现有实现成本单独决定。
保留有限 RTX，不把隧道变成无限重传层；泛用 IP 包没有视频关键帧语义。

### 3. FEC 保留完整机制，避免编码器与状态机重复建设

- 建议首先实现文档中的 RS/CM256 路径；ULPFEC、FlexFEC 是原媒体栈的其他格式，不自动成为组网协议的必选后端。
- 保留自适应保护、抑制/恢复迟滞、预算约束、RTX 联动及恢复统计。
- 原始包不等待编码组凑满才发；组按包数或最晚封组时间结束。
- 已收到的原始包及时交付，不因缺包给其他包制造全局有序等待。
- FEC 分组隔离 peer、方向、路径世代和密钥世代；编码失败与过期回收有明确上限。
- 原始包身份和每次发送序号分离；RTX 使用新的发送序号和加密 nonce。
- 网络实际到达与 FEC 恢复分别反馈，避免纠错掩盖原始丢包率。
- `K=109` 是原媒体路径参数，不等同于每个组固定等待 109 个包。
- 参数保留来源与单位；确证值用于初始配置和回归测试，场景适配项单独标注。

### 4. 去中心化不等于全连接

peers 用于引导；发现节点信息不自动建立所有节点之间的连接。
按通信需求建立直连，会话空闲后回收；发现信息有过期时间、数量上限、版本与来源。
第三方提供的候选地址只作为线索，实际会话需验证目标身份和路径。
候选收集优先事件驱动；打洞失败允许通过自愿承担中继能力的可达节点解密后按覆盖目的身份转发。
某些 NAT/防火墙组合下仍需要可达节点；去中心化消除的是固定服务依赖，不是底层可达性要求。

网络定位已定为私有组网且必须支持多跳。建议先采用一种轻量链路状态机制：节点发布自身已认证邻接关系，增量传播并计算下一跳，不额外叠加 DHT 与第二套路由协议。
规模目标已定为百节点日常使用、千节点验收；广播范围、状态容量、更新频率和连接度需据此设定上限。
拓扑变化、描述过期与撤销必须进入同一个收敛机制；转发带 hop limit，选路带迟滞，不靠逐包切路追逐瞬时 RTT。

#### 有界直连与默认 relay

已确认限制直连邻居数量，默认所有节点参与 relay。以下为建议默认策略，具体数值通过压力测试再冻结：

- 初始直连邻居上限建议为 16，合计入站与出站；同一节点的握手并发及探测速率也有独立上限。
- 显式配置的 peers 预留连接名额，其他名额用于按需直连和维持拓扑连通；配置数量超过总预算时报告配置冲突，不静默忽略。
- 通信先使用已有多跳路径；只有存在实际流量且有空位或值得替换的自动邻居时，才尝试直连优化。
- 优先回收闲置的自动捷径连接，保护配置入口与承担必要中转/拓扑维护的连接；替换使用先建立后撤销或预留名额，避免暂时切断唯一已知路径。
- 直连邻居与已发现节点分别计数；只有相邻节点建立加密会话。达到邻居上限时，其他目标继续经已有多跳路径通信，不建立全网端到端会话。
- relay 为已认证的覆盖网络流量执行用户态转发，不因默认开启而安装系统默认路由或开放系统内网转发。
- 本地流量和中继流量共享出口预算，并有公平调度、有界队列与背压；默认开启不代表无上限接收流量或无上限缓存。
- 节点发布 relay 开关与必要的可用性状态；资源紧张时反馈拥塞或撤销可用性，使选路避开过载节点，不反复创建更多直连连接。
- 达到上限、直连优化失败和 relay 资源不足应有可观测原因。控制面更新同样受去重、合并及速率限制约束。

当前实现采用 60 秒业务空闲计时、单向配置边保护和缓存的确定性保留图；
回收前校验保留图的跳数预算，具体规则与测试见 [邻居生命周期](neighbor-lifecycle.md)。

#### 成员信任传递

用户已确认允许传递成员信任。例如本机 A 信任 C，C 引荐 D，D 引荐 B，则 A 在验证引荐链和 B 的身份后可以自动与 B 通信。
这不要求 B 成为配置文件中的静态 peer，也不使 B 发布的子网或默认路由自动生效。
引荐关系与转发路径分开：A 可以经 C 获得 B 的可信身份，再直接连接 B；信任链不强制数据经过引荐人。

首次入网规则也已确认：A 配置 B 的地址及预期公钥；B 验证 A 在握手中证明持有其自身身份私钥，并在必要的密钥确认完成后自动接纳、产生引荐。A 无需出示此前已有成员签发的引荐才能连接该入口。
因此，这里的私有组网指部署和使用定位，而不是依赖秘密凭据的成员隔离：其他能够获得 B 公钥、访问其监听地址并完成握手的节点，同样可以被自动接纳。
签名与引荐用于防止伪造身份和记录，不用于证明新节点获得了人工批准；不得把这一模式描述为“只有获准用户才能加入”。

以下是实现建议，尚未冻结线格式与撤销规则：

- 引荐记录绑定引荐者与被引荐者的完整身份，附版本、有效期和可验证的签名；普通节点信息广播不自动视为引荐。
- 本机固定公钥配置的 peer，以及按已确认规则完成直接握手并自动接纳的节点，构成本机信任起点；后续引荐必须从这些起点可达。孤立的循环引荐本身不产生信任起点。
- 成员准入和直接邻接握手分别执行，验证拥有私钥而不仅是持有公钥字符串。
- 缓存验证结果并增量更新信任关系，不在每个数据包上重新验证整条引荐链。
- 信任关系有数量与消息大小上限，记录失效时清理缓存；本地明确封禁优先于任何引荐路径。
- 移除一个引荐关系只移除该信任路径；若存在其他有效路径，成员可能仍受信任。明确封禁与普通删除需要区分。
- 初始入站连接已确定自动接纳，多网络通过独立实例隔离；尚需确定撤销传播语义。连接数、握手速率和资源上限属于运行约束，不添加人工准入步骤。

#### 多跳与 trace 建议

- 多跳使用相邻节点认证加密链路。每个中继检查成员、跳数和目的路径，再解密/转发；不存在跨中继的端到端握手。声明来源由可信中继背书，最终 IP 来源/发布者规则仍校验。
- 直连是更短的候选路径，不是另一种不兼容的数据协议；直连恢复后按稳定性条件切回。
- trace 主动探测实际转发路径，显示节点身份、可读名称和探测 RTT；控制面算出的预计路径单独标注。
- 从源端测得的逐跳 RTT 不是每段链路延迟，不通过相减伪造单段单向延迟。
- 无响应、路径变化及返回路径不同都应显式展示；中继回复不等于目的已确认可达。
- FEC/BWE/RTX 按相邻链路作用域执行，每跳重新编码、反馈和有限重传。线上原始片、校验片和反馈全部经过该跳认证加密；接收端先认证再解码。没有叠加的端到端重传层。

### 5. Exit Node 与 Subnet Router 共用路由机制

用前缀发布、来源身份、本地接受策略、最长前缀匹配和撤销机制统一实现。
Exit Node 发布默认路由，Subnet Router 发布具体前缀；能力声明不等于客户端自动接受。
已确认发布项的身份是 `(发布节点, 规范化前缀)`；本机接受表为 `规范化前缀 → 一个选定发布节点`。
同一个目的 IP 匹配已接受前缀后，先确定发布节点，再通过覆盖网络路由到该节点，不让中继重新选择另一个同前缀发布者。
建议选定发布节点离线时保持不可达状态，不自动换到另一个同前缀发布者，因为它可能是另一张物理内网。路由撤销和出口失效的具体丢弃规则还需实现规格明确。
相同前缀的发布者切换须显式执行；不同长度的重叠前缀、已有流在切换时的处理仍是待决项。
实际转发还需实现双栈策略路由、回程路由或 SNAT、源地址校验、底层 UDP 路径防递归，以及退出时的状态清理。
Exit Node 失效保持阻断已确认。IPv4、IPv6 和 DNS 的具体接入实现遵循同一语义，不因出口失效而静默改走本地外网。

#### Exit Node 失效策略

已定产品行为：选择出口后保持对该出口的选择，失联只改变可用性，不自动选择本地出口或另一个 Exit Node。
同一个出口节点的底层路径可以在直连与多跳之间自动恢复；这不属于更换出口。
出口恢复后继续使用原选定节点。用户显式停用出口模式时，才解除出口约束并恢复被本实例接管的原有配置。

实现建议与验收约束：

- 区分 `disabled`、`selected/connecting`、`active`、`unreachable` 状态；重连中仍保留阻断规则。
- 开启出口模式采用先建立防直出约束、再切换路由的顺序；切换选定出口期间保留约束，避免瞬时直出窗口。
- 防直出约束由内核路由/防火墙状态执行，不仅依赖 TUN 仍然存在或进程主动丢包；进程异常退出和设备消失不应导致默认路由回落。
- 持久化用户选定的出口模式，启动时先协调恢复约束，再处理普通应用流量。开机阶段的约束安装顺序与 systemd 集成需单独验证，未覆盖该阶段前不宣称开机全程防直出。
- 出口缺少某一地址族的能力时，该地址族保持阻断并报告原因，不直接使用本机的另一地址族出口。
- DNS 流量同样遵守出口策略；DNS 配置与本机解析服务的接入方式待实现规格确定，不以本地回退作为容错。
- 覆盖网络自身的底层连接与必要恢复流量需要严格限定的例外，否则会把到出口节点的连接一起阻断；例外绑定本实例的受控 socket/标记，不给普通应用开放通用直出通道。
- 所有规则明确归属于实例，停用与清理只恢复本实例接管的配置，不覆盖系统其他网络管理器的无关状态。
- 规则部署、崩溃恢复和清理测试均先在隔离 network namespace 执行，不直接改动开发宿主机的默认路由或防火墙。

### 6. 性能首先来自约束明确的数据路径

缓冲区复用、有界队列、减少复制与系统调用、批量 I/O、单所有者状态优先。
批量收发同时限制批大小和最长等待时间，避免牺牲稀疏小包延迟。
先测量再加入 CPU 绑核、多队列和更复杂的执行模型；不预设每个包一个任务或层层跨线程 channel。
不预先引入 DPDK、AF_XDP 或自定义执行器作为实现前提。
PMTU、封装开销和 ICMP 错误处理属于基本正确性，不能仅凭固定 TUN MTU 判断链路可用。

### 7. IPv4 分配建议：分布式声明与确定性消解

不引入中心 DHCP 或共识集群。节点身份保持稳定，IPv4 是可更新的绑定。

1. 从节点身份与持久化探测计数派生 `/8` 内候选地址，启动时优先恢复已持久化绑定。
2. 传播经过身份认证的地址声明，携带地址、拥有者、单调版本及有效期信息；旧版本不覆盖新声明。
3. 同一 IPv4 有多个有效拥有者时，按完整节点 ID 的固定顺序选出胜者，其他节点推进探测计数后重新声明。
4. 新候选重复冲突时继续消解；更新声明、地址绑定和本地系统路由，并撤销旧映射。节点重启不能重置声明版本导致旧状态反复复活。
5. 通信按节点身份进行认证；接收端校验源 IP 与身份绑定。已知冲突的映射隔离处理，避免把包投递给另一个声明者。

该方案提供信息传播后的收敛，不声称分区期间全网立即唯一。分区合并要检测、消解并报告地址变化；依赖被改动 IPv4 的现有连接可能重建，节点身份和 IPv6 不随之改变。
定案时还需明确声明认证形式、过期与撤销语义、探测边界和地址空间耗尽行为。

## 待决问题（按依赖顺序）

1. **引荐生命周期**：MVP 使用 60 秒签名邻接记录、递增序号的邻接撤回，以及持久化本地公钥否定；
   实际直连才是本机信任起点，替代引荐有效，本地否定优先，详见 [成员策略](membership-policy.md)。
   首次入站自动接纳不变，不增加白名单、人工批准或邀请凭据要求；更大规模撤回/重放压力仍待验收。
2. **IPv4 地址策略细节**：自动分配与碰撞处理已确认；待确认消解后的地址变化体验及上述声明算法。
3. **路由策略细节**：手动接受与同前缀单发布者、出口失效保持阻断已确认；不同长度重叠前缀、出口选择粒度、DNS 接入方式、路由切换后的已有流行为待定。
4. **性能验收环境**：参考硬件、CPU 预算、目标吞吐与 PPS、并发 peer 数、满载尾延迟指标。
5. **协议落地项**：身份密钥绑定、握手与轮换、线格式、重放窗口、FEC 认证范围、反馈/恢复语义及参数边界。

`33.0.0.0/8` 保留用户要求，但它是已分配 IPv4 空间，不是私有地址段。
建议按已知节点安装 `/32` 路由，配合独立策略表与明确的底层路径选择，减少整段捕获；同一个目的地址的真实外网用途与 overlay 用途发生重合时，仍需要显式选择路由域。
地址池选择与路由实现分开记录，避免把“选定地址池”等同于“向主路由表注入整个 /8”。

## 验收建议

- 三节点：只配置引导 peer，经信息交换完成另外两点直连；中继回退、直连恢复、引导节点离线分别验证。
- 四节点：限制底层只允许 `A—C—D—B`，验证多跳握手、双向通信与 trace；再放开 A—B，验证直连升级、断链撤销、环路限制与 MTU。
- 稀疏网络：千节点规模下验证邻居上限同时约束入站与出站，发现节点不触发全网握手；达到上限仍可经多跳通信，连接替换不会无故撤销唯一已知路径。
- 默认 relay：验证转发公平性、队列与会话资源上限、过载反馈和 relay 关闭后的路由收敛；确认 relay 开启不自动开放 Exit Node 或系统内网转发。
- 多实例：在不同 namespace 内运行使用重叠地址池和重叠子网的实例，验证身份、状态、管理 socket、路由及 Exit Node 互不串扰。
- 地址：注入冲突、并发声明、旧声明重放、节点重启、网络分区后合并，验证消解收敛及身份绑定。
- 信任：验证跨多级引荐后的自动准入，隔离无可信起点的循环引荐，拒绝伪造或过期记录，测试撤销、替代引荐路径及本地封禁；确认子网路由不随成员引荐自动接受。
- 首次入网：仅 A 配置 B 的地址与公钥，B 无 A 白名单和批准操作，验证握手确认后自动接纳、引荐及第三节点发现；错误的 B 公钥、伪造私钥证明、未完成的握手和重放消息不触发引荐。
- 同前缀不同内网：B、C 各发布同一前缀，在同一内网 IP 部署不同标识的服务；只接受 B 时始终访问 B 的服务，B 离线不自动访问 C。
- 弱网：随机丢包、突发丢包、乱序、重复、限速、延迟变化、反馈丢失；FEC/RTX 逐项开关对照。
- 报告有效载荷吞吐、线上总带宽、PPS、CPU、内存、p50/p99/p999 排队与应用延迟，不把冗余计作有效吞吐。
- 路由：IPv4/IPv6、出口与子网双向回程、路由冲突、发布撤销、进程重启和清理。
- Exit Node：断开选定出口、切换底层路径、切换选定出口、强制终止 daemon、移除 TUN 和重启实例，抓包验证应用 IPv4/IPv6/DNS 不回退直出；确认底层恢复连接仍可工作，显式停用时恢复原配置。开机时序另行测试。
- 安全与健壮性：握手重放、伪造描述、nonce/序号边界、畸形包、FEC 资源上限、错误来源地址及路径迁移。
