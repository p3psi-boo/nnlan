# 逐跳路径 MTU

每条已认证 UDP 路径、每个发送方向各维护一份 PMTU。它改变外层分片大小，
不改变稳定的双栈 TUN MTU 1280；中继链路不必共享相同的下层 MTU。

## 探测与边界

- UDP payload 初始 548 字节（IPv4 MTU 576 减去基本 IP/UDP 头），上限 1452。
  先确认基础大小，再确认原 GGB3 上限 1232，最后尝试 1452；失败后在已确认值与失败上界之间二分，
  精度 16 字节。旧接收端忽略扩展探针时保留精确的已确认 1232，不降低正常数据大小。
- 独立 AEAD 加密的探针包含随机 token、目标 UDP 长度和零填充。接收者校验实际长度，
  返回小 ACK。只有当前密钥世代、当前已验证端点、匹配 token/长度且未过期的 ACK 可以提高大小。
  探针不经过 FEC/RTX，恢复或 IP 分片不会被误当成单个大报文可达的证据。
- 同时双向换钥允许两个发送方向选择不同的活动密钥世代。对方在本机保留的有效接收世代上
  发送的认证 Probe，仍在该世代回复；这不更新本机活动路径的源地址或 PMTU。
  ACK 则仍必须属于本机当前活动发送世代，不能用旧世代的反馈提高当前路径大小。
- 每种大小最多三次探测，超时 1 s；稳定路径每 5 s 验证当前大小，失败时退回基础大小重新探测。
  每 60 s 重新尝试提高上界，避免路径恢复后永久停留在小分片。探针和回复都计入实例总发送预算。
- Linux IPv4/IPv6 socket 使用 `PMTUDISC_PROBE`：禁止源端 IP 分片，并忽略 ICMP 路由缓存中的旧上界。
  本地 `EMSGSIZE` 降低对应端点的候选上界，不终止 daemon；ICMP PTB 不作为提高 PMTU 的证据。
  即使 PTB 被过滤，探针丢失仍触发收敛。当前没有直接消费错误队列中的 PTB MTU 值来加速下降。
- 密钥世代与路径状态分开：认证握手确认远端端点及本地收包地址均未改变时，保留已证实的大小、
  失败上界及统计，避免每次换钥都把在途队列降为 548 字节。新 Link 立即使用该大小，
  FEC、源片编号及加密状态仍按密钥世代隔离。
  取消旧的待确认探针，立即用新 token 在当前发送世代重新探测；未确认的大包不因换钥而晋升。
  远端端点或本地源地址改变时恢复基础大小，路径挑战迁移也先清空旧路径证明。
  状态量每邻居常数空间。
  `status.neighbors[].pmtu` 给出 payload、本地能力上限 `maximum_udp_payload`、确认状态、在探大小、发出/确认/失败/降级计数。
  `status.neighbors[].key_epoch` 是公开线上 session ID，用于核对实际换钥，不包含密钥材料。
- 548 以下的 UDP 可用大小不在当前支持范围；不会通过无限重试或开启 IP 分片掩盖失败。
  当前上限适配 1500 MTU（按 IPv6/UDP 头预算），小路径仍须按探测结果降级，不探测 jumbo frame。

## 分片、FEC 与反馈

UDP payload 减去 session 头 24、AEAD tag 16、源帧头 19 后，
得到最大编码片宽度 489–1393 字节；再减去 fragment 头 23，得到最大片段载荷 466–1370 字节。
单个消息仍最多 32768 字节，接收消息总字节数和片数均有上限。

组内所有 parity 使用同一宽度，取本组最长源片与 489 的较大值，不再强制填满路径上限。
改变 PMTU 前先封闭旧发送组，新组受新上限约束。
接收者从 parity 的认证长度得到补零宽度，校验源片与 parity 一致性；消息内非末片宽度一致。
ACK 按本方向可用大小拆分，避免小 MTU 仅能发出数据却收不到批量反馈。

下降时，队列中超出新大小的旧数据/FEC/反馈会被丢弃，旧在途缓存按既有有限 RTX/寿命收敛；
不重写已分配的源片序号、不混用新旧 FEC 组、不承诺 IP 报文可靠交付。

## 验证命令

```bash
nix develop --command make check
nix develop --command make e2e-pmtu
nix develop --command make scale-rekey
```

`tests/e2e/pmtu_netns.py` 在本次创建的 A–路由器–B namespace 中验证：

1. 正常路径探测到 UDP 上限；缩小远端链路，分别触发路由器 ICMP PTB 和本地 EMSGSIZE。
2. 单向静默大包丢弃，验证两个方向独立收敛。
3. IPv4 下层 MTU 576 且过滤 PTB，完整大小的双栈 TUN ICMP 与 16 KiB 加密 echo 继续通信。
4. 恢复 MTU 后自动增大，无 daemon 重启。
5. IPv6 下层 MTU 1280 上双栈覆盖通信。

每阶段核对内核 IPv4 IP 分片计数、daemon boot ID，并记录二进制/脚本哈希。
这不是完整路径组合、超高时延或复杂 ICMP 扩展头验收；隧道外部路由的 ICMP 错误传播仍需扩展测试。

常规测试还使用真实 UDP socket、受控握手交付顺序制造交叉换钥，确认两个活动发送世代不同；
两个方向均须重新探测到当前本地能力上限，随后互发 8192 字节消息。
原有旧世代 ACK / 非已验证端点拒绝测试保留。
另以真实 UDP 验证同路径换钥后保留完整 PMTU、8192 字节旧世代待发消息仍能交付，
以及端点挑战迁移、同身份从新端点重新握手都必须回到未确认的基础大小。
探测器单元测试覆盖旧 token 失效、失败上界保留及本地错误仍能降级。
`scale-rekey` 使用 100 个真实 daemon、135 s 稳态，让生产环境的 120 s 换钥定时器自然触发；
核对每条有向邻接的世代确实变化、全部 PMTU 恢复，并再次执行全节点加密回显及双向多跳 trace。
具体运行结果与边界见 [规模测试](scale-testing.md)，命令本身不代表已通过。

设计参考：[RFC 8899](https://www.rfc-editor.org/rfc/rfc8899.html) 的报文层探测机制；
socket 选项由 [rustix sockopt](https://docs.rs/rustix/1.1.5/rustix/net/sockopt/index.html) 提供安全 Rust 接口。
这里明确列出实际定时器与范围，不声称通过完整 RFC 一致性认证。
