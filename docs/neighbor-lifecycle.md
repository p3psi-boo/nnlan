# 有界邻居与空闲回收

节点发现不会触发全网握手。应用流量先经现有覆盖路由转发，再尝试按需直连；
入站/出站连接共享 `max_neighbors`，配置 peer 预留名额。没有可回收名额时继续多跳，
不为建立捷径而强行删除唯一已知路径。

## 什么算空闲

默认 **60 秒没有覆盖业务流量**才进入自动连接回收候选，每秒最多发起一次回收。
发送、接收和中继的有效 Envelope 都计入使用时间，包括用户发起的 trace/echo；逐跳保活不延长业务空闲期限。
LSA、邻接 keepalive、PMTU、ACK/FEC 控制和自动换钥不更新业务使用时间。

这与链路的 6 秒认证活动超时不同：

- `status.neighbors[].idle_ms`：多久没有认证链路活动。
- `status.neighbors[].traffic_idle_ms`：多久没有覆盖业务使用。
- `status.idle_retired`：本机主动回收的累计连接数。

同一节点换钥/迁移保留业务使用时间；新邻居从当前时间开始计算。
回收完成后清理邻居名额、全部相邻密钥/FEC 实例、握手重试地址和路径挑战，撤回邻接与候选观察。
回收捷径后，业务仍可使用现有多跳链路；后续真实流量可以重新触发直连，没有独立端到端会话需要保留。

## 配置入口保护

节点签名描述新增 `pinned`：指向排序后的 `neighbors` 的索引数组，而不是重复一组公钥。
索引必须递增、无重复且在邻接范围内，数量最多 128，随同原有描述签名和过期。
发布者只标记当前已连接、且在本机配置 `peers` 中的邻居。

一条边只要任一端标记为配置连接，两端都保留它，避免 B 把 A 单向配置的 A→B 当作闲置捷径删掉。
收到第一份对端签名描述之前，保护策略属于未知状态，不据此回收连接。
这只是连接生命周期信息，不扩大成员资格、子网接受或 Exit Node 选择权限。
`pinned` 是签名负载的必需字段；旧描述不会被当作“无配置保护”接纳，部署时各节点使用本次协议构建。

## 为什么并发回收不会把一个环全拆掉

只检查“删掉自己这条边后还有另一条路”不够：环上的节点可能同时做出相同判断，最后一起断开。
本实现为自动边定义全序 `(较小端点公钥, 较大端点公钥)`，拓扑变化后，在首次实际回收候选检查时按需构建保留图：

1. 保留配置边，以及与非 relay 节点相连的边，后者采用保守的接入保护。
2. 对 relay 节点按边全序执行 Kruskal 合并，补齐连接各 relay 分量的必要骨架。
3. 只有保留图之外的空闲边才考虑回收，备用路径必须完全位于保留图。
4. 每个 relay 分量选公钥最小的 relay 作为检查中心。保留图上该中心到所有可达端点的距离都不超过 16 跳，
   才允许此分量回收捷径。这是充分而非必要条件：保守留下额外连接，好过回收到超过报文 32 跳上限的图。
5. 由公钥较小的一端发起回收，双方不重复协调同一条边；每秒最多一条。

配置边不会被回收，Kruskal 骨架不受删除非骨架边影响，因此对一致的稳定拓扑，各节点得到相同保留图。
并发删除的捷径不出现在对方的备用路径中；经过中心的真实保留路径仍在 32 跳内。
即使撤回传播有延迟，也不会互相依赖待删捷径而一起拆掉一个环。
入口掉线后，必要自动骨架会留下；非 relay 节点不会充当隐含的备用中继。

只限制单条边当前的备用路径长度仍然不够：例如 40 节点链上两条捷径各有 20 跳备份，
同时删掉后，原本 3 跳可达的首尾会变成 39 跳。回归测试专门覆盖这个反例。
配置保护边无需构建保留图；其他空闲候选首次检查时计算，结果缓存到拓扑变化时失效。
因此纯配置树和不发生回收的发现阶段不反复计算保留图，也不放进逐包数据热路径。

这不是原子网络事务：并发的真实链路故障、过期前的远端描述或资源故障仍可能让预测路径失效，
它们沿现有失联检测、描述过期和重新发现机制恢复。回收规则不把控制面预测伪装成主动 trace。

## 关闭通知

发送端在当前已认证路径/密钥下发送一个小型 AEAD 关闭通知，然后撤回本地连接。
接收端只接受当前路径和当前密钥世代的通知，旧世代延迟通知不关闭新连接。
通知丢失时，对端采用已有的 6 秒失联超时；不新增一套无限重传或分布式关闭事务。
该短暂窗口可能丢弃在途 IP 报文，与路径迁移的报文语义一致。

## 验证

```bash
nix develop --command make check
nix develop --command make e2e-neighbors
```

普通测试包括：

- 遍历五节点的全部 1024 种无向图，每种同时检查有/无配置保护边；基于删除前快照一次性删去所有可回收边，验证所有连通分量保留。
- 必要桥接边、非 relay 接入和超过跳数预算的保留图不触发回收。
- 远端单向配置保护、本地配置预留、签名索引边界，以及未知/过期拓扑约束。
- 换钥/控制流量不重置业务空闲时间；当前世代关闭、资源清理、再次接入、旧世代关闭隔离。

`tests/e2e/neighbors_netns.py` 使用真实 daemon、Linux TUN 和生产 60 秒计时器，
测试满额时继续多跳、闲置名额复用、单向活跃流量保留、入口进程退出后的必要自动桥接，
以及四节点自动完全图同时回收到连通稀疏图。报告写入 `target/e2e-neighbors.json`。
测试只操作本次创建的 namespace，不修改宿主机网络。
